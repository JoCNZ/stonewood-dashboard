How to Set Up Claude Skills for Property Development

Stop repeating yourself to AI. Build Skills once—reuse them across every project, every tenancy, every capital decision. Here's how to set up Claude so it works like a trained member of the Stonewood team.

Why This Matters for Stonewood

Right now, too much execution still runs through founder intervention rather than an operating system. Every time someone opens a blank Claude chat to draft a contractor email, summarise a QS report, or chase a deadline—they're starting from zero.

Skills fix this. A Skill is a reusable instruction set that lives inside Claude. You invoke it with a slash command—like /brief or /chase-note—and Claude instantly knows your format, your tone, your standards. No context-setting. No re-explaining Stonewood's way of doing things.

Think of it this way: A prompt is telling a stranger your job every morning. A Project is giving a new hire a binder on day one. A Skill is training an employee once—permanently.

Step 1: Get Set Up (10 minutes)

1 Download the Claude desktop app

Go to claude.com/download and install the desktop app. You need a Pro plan ($20/month)—it's worth it for the model access alone.

2 Open Cowork and configure it

Click the Cowork tab at the top. This is where you'll spend 80% of your time. Set these and never change them:

  • Model: Opus 4.6
  • Toggle on: Extended Thinking (forces Claude to reason before answering—critical for capital decisions and contract reviews)
3 Create your Stonewood Cowork folder

On your PC, create a folder called Stonewood-Cowork. Inside, create these subfolders:

  • ABOUT-STONEWOOD — company context, project summaries, team roles
  • TEMPLATES — email templates, report formats, meeting agendas
  • PROJECTS — one subfolder per active project (280 Queen St, Willis St EV, 318 Retail, etc.)
  • OUTPUTS — Claude-generated deliverables you want to keep

Point Claude's Cowork to this folder. Now it has persistent context about your business.

Step 2: Build Your First Skill (15 minutes)

A Skill is a long instruction + context that Claude stores and fires when you invoke it. Two ways to create one:

A Use Claude's Skill Creator
  1. Open Claude and describe the task you want automated
  2. Claude interviews you—answer its questions about format, tone, and standards
  3. It generates the Skill automatically
  4. Test it, refine it, save it
B Write it yourself (a .md text file)
  1. Create a new markdown file (e.g. skill-chase-note.md)
  2. Write the instruction: role, context, format, tone, examples
  3. Drop it into your Cowork folder
  4. Invoke it with /chase-note in any conversation

Pro tip: The game is text files. Take everything Stonewood knows—your writing style, your contract language, your reporting standards, your delegation rules—and put it in .md files. Drop them in the Cowork folder. Claude absorbs all of it.

7 Skills Every Stonewood Team Member Should Have

/chase-note

Generates a firm, direct follow-up email for overdue action items. Input: task description, owner name, original deadline. Output: chase email in Stonewood's accountability tone—no fluff, named owner, hard deadline, escalation path.

/project-brief

Creates a one-page project status brief from raw notes or meeting minutes. Structured as: project name, status (Red/Amber/Green), key milestones, blockers, capital position, next 7-day actions with named owners.

/contract-review

Reviews a draft contract or variation and flags risk items. Checks for: missing liability caps, unclear payment terms, penalty clauses, consent requirements, insurance gaps. Outputs a risk summary table with recommended actions.

/qs-summary

Takes a QS report or cost schedule and produces a plain-language executive summary. Highlights variances above 5%, flags provisional sums at risk, and recommends questions for the next QS meeting.

/tenant-comms

Drafts tenant-facing communications (lease updates, maintenance notices, rent reviews). Matches Stonewood's professional-but-firm tone. Input: situation, key message, any deadlines. Output: ready-to-send email.

/weekly-report

Compiles a structured weekly project report from action register data. Sections: completed this week, in-progress, blocked, escalations, capital drawdown status. Follows Stonewood's reporting format exactly.

/capital-memo

Drafts an internal capital deployment memo for founder review. Structures the case as: opportunity summary, capital required, risk assessment, expected return, recommendation. Direct language, no padding.

Step 3: Share Skills Across the Team

Skills aren't just personal—they're how you build an operating system that doesn't depend on any one person.

  1. Export your Skills as .md files into a shared drive or repo
  2. Team members import them into their own Cowork folders
  3. Everyone uses the same /commands—same format, same tone, same standards
  4. Update centrally—when a template changes, update the .md file and redistribute

The goal: Any project manager, finance controller, or ops lead at Stonewood should be able to type /chase-note and get output that's indistinguishable from what John or Michael would write. That's programme-led execution—not founder-dependent execution.

Step 4: One Project per Stonewood Development

Inside Cowork, create a Project for each active development:

  • 280 Queen Street / Radisson — drop in: hotel specs, Radisson brand guidelines, close-out checklist, rooftop bar timeline
  • Willis Street EV Redevelopment — drop in: resource consent docs, EV charger specs, mixed-use feasibility notes
  • 318 Retail — drop in: tenant schedules, lease terms, fitout standards
  • Balmain Settlement — drop in: settlement docs, final accounts, defects register

Projects have scoped memory—say "build on last week's QS report" and Claude knows exactly which report you mean. No re-uploading. No re-explaining.

The Bottom Line

30 minutes of setup today saves hours of re-explaining every week.

The shift is simple:

  • Before: Email-driven execution. Every AI interaction starts from scratch. Output quality depends on who's prompting.
  • After: Programme-led execution. Skills encode Stonewood's standards. Anyone on the team gets consistent, high-quality output. Founders focus on capital and strategy—not chasing emails.
